# Unigine v0.2

Unigine engine version 0.2 from http://frustum.org

With a modern build system.

## The layers

Every layer is a static library, a layer only uses the layers below it. The
include paths of a library hold the public headers of that layer alone, so a
layer can not reach the ones above it.

| layer | library | uses |
|---|---|---|
| the foundation | `Core` | |
| the data file language | `Script` | Core |
| the platform | `Platform` | Core |
| the rendering api | `RenderApi` | Core, Script |
| the graphics backend | `RenderGl` | RenderApi, Platform, Core, Script |
| the scene | `Scene` | RenderApi, Core, Script |
| the engine | `Engine` | Scene, RenderGl, RenderApi, Platform, Core, Script |

The rendering api is the contract of the device: the geometry, the programs,
the textures, the materials and the state of the frame. The backend maps them
onto OpenGL, it is the only layer that names a graphics api. The scene draws
through the api, the engine drives the frame.

The script library holds the language of the data files: the preprocessor that
reads the maps, the materials and the shaders, and the expressions it
evaluates.

## Requirements

Development is done with
* Conan 2.x
* CMake 3.27.x
* Visual Studio 2026 Community Edition

## Building

Conan install for debug and release builds
```
conan install . --build=missing --settings=build_type=Debug
conan install . --build=missing --settings=build_type=Release
```

CMake project generation

```
cmake --preset conan-default
```

Build and test
```
cmake --build build --config Debug
cmake --build build --config Release
ctest --test-dir build -C Debug
ctest --test-dir build -C Release
```

The `conan-default` configure preset is generated by `conan install`. On Linux the
single-config generator puts the binaries in `build/Debug` and `build/Release`.

## Running

The demo opens a window and waits for the keyboard and the mouse.

```
App.exe
```

It also runs without a window, which is what the tests use. The frames are
rendered with a fixed timestep, so two runs give the same frame.

```
App.exe -frames 60 -shot frame.png
```

- `-frames <n>` renders `<n>` frames and stops, without a window
- `-shot <file>` writes the last frame as a png
- `-w <n>`, `-h <n>`, `-fs` set the window size and the fullscreen mode
- `-wireframe` draws the whole scene as white lines

The PNG contains the app's final framebuffer, including the scene presentation
and overlays, captured before the buffer swap.

The `ctest` run of the `headless` test does the same and leaves the frame in
the build folder.

The first error the driver reports stops the app, the log holds the stack of
the call that failed.

## Features

From the original release:
- text preprocessor with simple language
- console
- bsp trees with portals
- triangle strips
- skinned mesh
- particle systems
- shadow from all objects
- volumetric fog (based on convex meshes)
- mirrors
- per-pixel lighting
- work on all video cards begining fron Geforce2
- horizon selfshadowing
- offset bumpmapping
- collisions
- rigidbody physics
- joints
- ragdoll
